`../silero.ts` imports the model and these npm assets with Bun's `type: 'file'` loader:

| `dist/ort-wasm-simd-threaded.wasm` | 11,210,254 | `71aef04959c5c1b6de461b6538e2058e306610034a85aad2742d0c7fd4533fe4` |

Bun embeds these files in compiled binaries. WASM is read into `env.wasm.wasmBinary`; `wasmPaths.mjs` points to the embedded
module. ORT's default sibling-module lookup does not work at Bun's compiled virtual URL, so the explicit MJS override is
necessary. No runtime download occurs. Only the WASM backend is enabled, with one thread and no proxy worker. One lazy
session is shared; every window owns fresh recurrent state and context.

Post-processing follows the pinned upstream `get_speech_timestamps` defaults: threshold 0.5, negative threshold 0.35,
minimum speech 250 ms, minimum silence 100 ms, padding 30 ms, 512-sample frames and 64-sample context at 16 kHz. The final
frame is zero-padded and intervals are clipped to decoded samples. Unlike upstream's optional rounded `return_seconds`
output, the boundary preserves fractional seconds and adds the media window start. No detection thresholds were tuned.

On macOS arm64 (Apple M5), Bun 1.4.4 and ffmpeg 8.1.1, eight 40-second windows at 6%, 18%, ..., 90% of a 480-second
loop of the generated speech fixture took **1.653 s cold** and **1.551 s warm**, including decoding and VAD (320 seconds
of audio, 42 intervals). The compiled offline smoke's complete accuracy/repetition/state-isolation checks took **0.782 s**
inside the binary; the automated compile-and-run test took approximately 2.1 s.

The npm package's production closure is 18 packages, **100,743,687 bytes** of installed files (96.08 MiB) and
**21,704,817 bytes** of downloaded npm tarballs (20.70 MiB). This counts the complete package closure, not just embedded
WASM/model assets; some dependencies were already present as development dependencies. `nix/deps.json` is generated by
postinstall, not hand-edited.
