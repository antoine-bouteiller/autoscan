## 2. Problem Statement

Subtitle files reach the library from Bazarr downloads, Bazarr translations, and transcoding extraction, and some of them are wrong: a full-dialogue slot filled by a forced track, a track offset or drifting from the speech, a truncated track, or a track made for another cut or episode. Other media stay without subtitles for days because no provider has them, and French-audio media keep requesting full subtitles they never need. The feature is a scheduled, incremental scan that judges English tracks against sampled speech and other languages against a speech-verified English track, repairs what it can through Bazarr, blacklists or alerts on what it cannot, and keeps Bazarr's per-media language requests aligned with the audio actually played.

- `[G-1.1]` Analyze non-forced sidecars on episodes and movies without French preferred audio once per file identity (full path, size, and mtime) and scan version; never re-analyze a file whose current-version `passed`, `invalid`, or `inconclusive` row still matches its size and mtime.
- `[G-2.1]` Remove unwanted forced subtitles through Bazarr, and repair a constant offset or linear drift through Bazarr, verified in the same pass. A track that cannot be repaired, or is still misaligned after its repair, becomes `invalid`; a track whose evidence is too weak to decide becomes `inconclusive`.
- `[G-3.1]` For media missing subtitles for more than 3 days, alert on Telegram when none exist and translate through Bazarr when a usable source exists; a translation into a non-English language starts only from an English track verified against speech.
- `[G-4]` Keep only forced sidecars on French-audio movies: assign the Bazarr French preset, remove existing non-forced sidecars through Bazarr, and release the forced request after 7 days without one.
- `[G-5.1]` Judge every English sidecar against sampled speech of the media's original-language audio, alone or paired, once the transcode scan has passed the media, and judge every other language by text against a speech-verified English track. A track in sync with the audio is never `invalid` because of an unverified or differently segmented sibling. A pass samples at most once per media and at most `SPEECH_MEDIA_PER_PASS` media.
- `[G-6]` Stop Bazarr from downloading an invalid provider subtitle again: the scan blacklists a provider-downloaded track that is `invalid` without a repair attempt, and the Telegram delete button blacklists when Bazarr history names the provider.

## 4. Principles & Intents

- `[PI-1.1]` Incremental by default — file analysis over a library whose sidecars all have counting current-version rows performs directory listings, registry lookups, and one stat per sidecar, without hashing or reading subtitle contents. Mutations are triggered by an unregistered path, a changed size or mtime, a scan-version bump, or an elapsed window.
- `[PI-2.1]` Bazarr owns subtitle files — deletion, blacklisting, offset and framerate mods, translation, and download are Bazarr requests; the feature never writes a subtitle file itself.
- `[PI-3]` Per-item resilience — a media, Bazarr, or filesystem failure is logged and the traversal continues, as in `src/features/language_sync/jobs/language.job.ts:20`.
- `[PI-4]` Act once — every time-window action (alert, translate, release) is recorded so a daily cadence never repeats it.
- `[PI-5]` Evidence per track — a verdict cites evidence about that file: speech for English, and the pair profile against a speech-verified English track for other languages. An unverified track neither passes nor condemns another.
- `[PI-6]` Abstain when unsure — weak evidence records `inconclusive`, which never alerts, repairs, or blacklists.

## 5. Non-Goals

- `[NG-1.1]` Local subtitle rewrites, transcription, translation-quality/content checks, full-media audio analysis, and speech assessment of non-English tracks. Speech evidence is sampled VAD on English tracks; neither timings nor sampled speech certify dialogue content.
- `[NG-2]` Choosing subtitle providers, scores, or languages beyond the profiles configured in Bazarr.
- `[NG-3]` Scanning subtitle streams embedded in the media container; only sidecar `.srt` files are analyzed.
- `[NG-4.1]` Reporting a per-pass summary to Telegram; only all-missing alerts, invalid-subtitle alerts, automatic-blacklist alerts, and replies to `/subtitlescan` and `/invalidsubtitles` are user-facing.

## 6. Caveats

- `[C-1]` Bazarr, Plex, and this service must see the same file paths; item lookup matches Bazarr's `path` against the Plex part path, like `src/integrations/arr/sonarr.service.ts:34`.
- `[C-2.1]` The forced heuristic requires the media duration, which comes from an ffprobe of the media file (`src/features/transcoding/services/helpers/subtitle.ts:18`). The probe runs only for episodes or non-French-audio movies with at least one candidate: a non-forced sidecar without a counting current-version row.
- `[C-3.1]` Non-English tracks stay unjudged and never alert while their media has no reference: no English sidecar, an English track that is `invalid` or `inconclusive`, a media that never passes the transcode scan (for example after `NoStreamsKeptError`), or a stream check that keeps failing. An `inconclusive` English track is terminal for its file, so it blocks its siblings until the file changes.
- `[C-4.1]` A same-path file with the stored size and mtime reuses the current-version verdict; a different size or mtime, a rename, or a version bump makes the path a candidate. A file whose stats differ around its read gets no row in that pass, and a file can still change between the last stat and Bazarr's rewrite. A verdict is not revisited when something it depends on changes later: a non-English `passed` row survives a later change of its English reference, and an English `passed` row survives a same-path replacement of the media file. Deleting the file removes its row after the next traversal (`[KD-3.2]`) or immediately through the delete action (`[KD-15.1]`).
- `[C-5.1]` Wanted lists, items, subtitles, and profiles (`/api/movies/wanted`, `/api/episodes/wanted`, `/api/subtitles`, `/api/system/languages/profiles`, `/api/movies`, `/api/episodes`) follow Bazarr 1.4; history, blacklist, and mod requests follow Bazarr 1.6.2's API and mod source as read on the host, not a live call. The integration validators pin the fields the feature reads and must be checked against the deployed version. Blacklisting starts an immediate Bazarr search, so a replacement can arrive within the same pass.
- `[C-6]` The French preset is resolved by name from `BAZARR_FRENCH_PROFILE`; a missing profile is logged and prevents assignment and cleanup for French movies without an existing profile row. Previously assigned or released French movies can still have non-forced sidecars removed. French movies skip normal file analysis; other media's scan and the missing-subtitle policy continue.
- `[C-7]` Releasing a profile sets the Bazarr item's language profile to none; Bazarr then stops listing it as wanted, so the `released` state lives only in this feature's table.
- `[C-8]` Missing-subtitle rows are removed when the `(item, language)` leaves Bazarr's wanted list, so a subtitle that later disappears restarts the 3-day clock.
- `[C-9.1]` A translation into English uses the first present non-forced subtitle of the item as source; a translation into another language uses a speech-verified English sidecar (`[KD-19]`). Bazarr chooses the translation engine. A translation whose history entry is gone, or that was made outside Bazarr, counts as an original: its checks are the same, only the blacklist attempt differs.
- `[C-10.1]` Thresholds are constants in `src/features/subtitle_scan/constants.ts`, without environment settings, and are in-sample: one library, 44 media, English and French, with Whisper word timestamps standing in for Silero output. Tuning against the audit corpus set `AGREE_TOLERANCE` to 1.5 s, `PROFILE_SMOOTH` to 0.2 s, `SEGMENT_PEAK_RATIO` to 1.2, `ALIGNED_MIN_R` to 0.41, `MARGIN_MIN` to 0.05, and `REPAIR_MAX_RESIDUAL` to 1 s; 19 of the 22 audited in-sync English tracks are `aligned`, above the floor of 18 that `[VC-9.1]` sets. Silero on ONNX Runtime Web runs offline in a compiled macOS arm64 binary (`tests/integrations/ffmpeg/compiled.spec.ts`). On Linux, the `speech-offline` flake check runs the same smoke in the network-less build sandbox; CI builds it with the x86_64 package. `[VC-14]` and `[VC-17]` gate shipping the audio parts.
- `[C-11.1]` Eight 40 s windows cannot certify unsampled scenes: a local defect between windows can pass. Small drifts under about 3 s tend to stay `inconclusive`, and a drift that is not a framerate ratio smears each window: Desperate Housewives S01E04 en (about 5.4 %) comes out `inconclusive`, not `linear`. Neither timings nor VAD prove which dialogue a track carries.
- `[C-12]` The transcode precondition accepts a row at any transcode version and inherits that registry's same-path reuse (`src/features/transcoding/transcoding.spec.md` `[C-5]`): a media replaced at the same path without a new transcode check is sampled on the old layout's assumption.
- `[C-13]` The version-3 bump re-reads about 1,430 sidecars once and samples every media with an English sidecar and a transcode row, 60 per pass: an estimated 1–5 hours of host time spread over about 13 passes. A media whose sampling keeps failing consumes a cap slot on every pass; there is no retry scheduler.

## 8. Detailed Design

### Scan job

`runSubtitleScan` acquires a single scan permit (an item is skipped, not queued, when a pass is running), reads Plex sections and media, resolves `getCompleteMediaDetails` per item, and applies `applyFrenchProfilePolicy` first for French-audio movies, skipping `scanMediaSubtitles` for them; other media run `scanMediaSubtitles`. `pruneMissingScans` and then `applyMissingPolicy` run once per pass after traversal, even when traversal fails; the missing policy runs there because it is driven by Bazarr's wanted list rather than by Plex items. Non-interruption failures per item are logged with the media title and the loop continues; the job's own failure is logged at the scheduler boundary.

Each pass traverses every Plex section and analyzes every media item with candidate non-forced subtitle paths: sidecars without a counting current-version row (`[KD-2.2]`). French-audio movies skip file analysis, even when cleanup fails. Media whose sidecars all have counting rows are skipped after one stat per sidecar, without content reads. The pass keeps the set of media it has sampled and stops sampling at `SPEECH_MEDIA_PER_PASS` (`[KD-16]`); English candidates past the cap wait for a later pass. Analysis failures leave paths unregistered, so the next pass retries them. Missing-subtitle reconciliation, translations, and alerts remain library-wide and run after traversal.

- `[SO-4.1]` One pass analyzes every candidate path across all sections; French-audio movies and media whose sidecars all have counting current-version rows skip analysis — demonstrated by `[VC-5]` and `[VC-12.1]`.
- `[VC-5]` Job tests verify a single pass analyzes all new candidates across sections, skips French-audio, cached, and forced-only media, continues past metadata and analysis failures, and a following manual pass retries only the failed path — demonstrates `[SO-4.1]`. Terminal inconclusive eligibility is additionally covered by `[VC-12.1]`.

`/subtitlescan` submits the same pass to `BackgroundTasks`, replies `Starting subtitle scan...` or `A subtitle scan is already running.` according to permit admission, and returns `{ step: 'idle' }`; it produces no report (`[NG-4.1]`).

### Scan registry

The feature owns `SUBTITLE_SCAN_VERSION = 3`, a positive integer constant shared by `/subtitlescan` and the scheduled pass. Version 3 introduced the speech and pair-profile verdicts, Bazarr repairs, and blacklisting; its bump re-analyses every sidecar once (`[C-13]`). After a bump, the next pass treats every path without a row at the new version as a candidate, including old `passed`, `sync_requested`, or `invalid` paths. Old verdicts are neither skip signals nor references. A bump does not launch a pass itself; the schedule or command does.

Version bumps increase monotonically and are not reused; compatible relaxations may retain the current version. A row is valid only when its stored version matches the current version; a successful re-analysis replaces the row for that path with the new version and verdict, so no historical versions are retained and no registry purge is needed. The version is not a Telegram argument or environment setting. It does not reset `missingSubtitles` clocks/action markers or `frenchProfiles` lifecycle state, and it does not invalidate transcode results.

Repository functions follow `src/domains/media/repositories/media.repository.ts`: each runs a Bun SQL query in `Database.use` and maps rejections to `DatabaseQueryError`. Lookups require both `filePath` and the current scan version; the caller then compares the stored size and mtime with a fresh stat (`isCounting` in `src/features/subtitle_scan/services/scan_registry.service.ts`). `subtitle_scans` writes use `ON CONFLICT (file_path) DO UPDATE` with every non-key column from `EXCLUDED`, replacing the entire row after a successful analysis so each full path has one latest record. Row types live in `src/database/schema.ts` and the tables are created by migrations under `migrations/`. `migrations/20260921190858_scan_path_primary_keys` updates both scan tables, retaining the latest record per full path by `scanned_at DESC, ctid DESC` before making inline `filePath` its sole primary key.

Records survive restarts and have no time-based expiry. Scheduled and manual passes use the same registry: a path whose row counts is not analyzed again. A row stores the stat of the snapshot it judged: after a repair, the re-read's, so a repaired file is not a candidate on the next pass; after a blacklist, the judged snapshot's, so the deleted file's row is pruned and a replacement at the same path is a new identity. Only `passed` English rows with evidence `audio` serve as references (`[KD-17]`). Forced-looking sidecars deleted through Bazarr leave no row, so a later file at that path is a new candidate. A path whose file was deleted loses its row on the next pass when its parent directory still exists, or immediately through the delete action; a later file at that path is then a new candidate. Failed or interrupted analysis never records a verdict, and a failed registry write leaves the path eligible for a later pass.

`migrations/20260923115940_invalid_subtitle_verdict` added `invalid`, and `migrations/20261118120000_subtitle_identity` adds `inconclusive`, the evidence enum, and the nullable stat and evidence columns, both without changing existing rows; `sync_requested` stays in the enum. Rollback is compatible for code and schema only: version-2 code ignores the new columns and filters by version, so version-3 rows, including `inconclusive`, are invisible to it. Because each path keeps one row, version-3 rows have replaced version-2 rows, so rolled-back code re-analyses those files with version-2 behaviour, including sync requests. Repairs, deletions, and blacklist entries made through Bazarr are not undone. Pause the Subtitle Scan job before rolling back if that re-analysis is unwanted.

This registry is independent of the passed-file registry in `src/features/transcoding/transcoding.spec.md`, except that the scan reads `transcode_scans` as a precondition for sampling speech (`[KD-12.1]`), through its own `src/features/subtitle_scan/repositories/transcode_scan.repository.ts` (`hasTranscodeScan(filePath, originalLanguage)`, any transcode version). A successfully checked media file skips further transcode analysis for that identity, not subtitle analysis or the missing/French policies. Transcoding never marks extracted sidecars as passed: new sidecar paths enter this scan as candidates. Conversely, a passing subtitle does not certify the media's transcode criteria.

### Analysis service

For media other than French-audio movies, `scanMediaSubtitles` (`src/features/subtitle_scan/services/subtitle_scan.service.ts`) lists sibling files `<base>.<lang>.srt` and `<base>.<lang>.forced.srt` in the media directory, then:

```text
candidates ← sidecars without a `.forced.` marker and without a counting row   # one stat per sidecar ([KD-2.2])
if candidates is empty → return              # no content reads, probe, Bazarr lookup, or audio
item ← Bazarr item of the media; none → log a warning, return
read each candidate between two stats; stats differ → dropped for this pass
duration ← ffprobe(media)
forced-looking candidates → bazarr.deleteSubtitle; no row; dropped below          ([KD-4.1])
english ← remaining candidates in REFERENCE_LANGUAGE
if english is non-empty, the media has a transcode row for its original language,
   exactly one audio stream is tagged with that language, the media is not yet
   sampled this pass, and the cap is not reached                       ([KD-12.1], [KD-16]):
  add the media to the sampled set; windows ← sampleSpeech(media, that stream, 8 × 40 s)
  for each English candidate: judge(assessTrack(track, windows))
otherwise English candidates wait without rows (a warning when the stream check fails)
reference ← English sidecar with a counting passed/audio row, smallest path ([KD-17]); none → others wait
read the reference between two stats if not yet read; stats differ → others wait
for each non-English candidate: judge(profilePair(reference, track, duration), coverage) ([KD-5.1], [KD-11.1])

judge:
  in sync (aligned, or agree with coverage) → passed with evidence audio or reference
  constant | linear                         → modifySubtitle(fit); re-read; judge once more, without repair:
                                              in sync → passed; weak → inconclusive; otherwise → invalid, alert
  weak (inconclusive, undetermined)         → inconclusive
  otherwise                                 → invalid, blacklist ([KD-18])
```

Each verdict is persisted with its snapshot's stat (`[KD-3.3]`). A repair or blacklist runs only when a fresh stat equals the snapshot's; a file that changed gets no Bazarr request, no row, and no alert. History sources are fetched at most once per media. A failure for one track (read, stat, Bazarr repair, I/O) leaves that track without a row and the pass continues with the next track; a failure for the English reference makes the non-English candidates wait. A failure for the media (ffprobe, the transcode lookup, the audio-stream probe, `sampleSpeech`) leaves every candidate of the media without a row. Rows written earlier stay, and interruption propagates. A failed blacklist call is not a failure: the `invalid` row persists and the alert keeps its delete button. Classification rules live in `src/features/subtitle_scan/services/subtitle_profile.ts` and `src/features/subtitle_scan/services/subtitle_alignment.ts`, and their thresholds in `src/features/subtitle_scan/constants.ts` (`[C-10.1]`). `parseCues` and the forced heuristic handle LF and CRLF.

```ts
// src/integrations/ffmpeg/ffmpeg.service.ts — read-only
interface SpeechWindow {
  readonly start: number // media seconds
  readonly duration: number
  readonly speech: readonly (readonly [number, number])[] // media seconds
}
readonly sampleSpeech: (
  input: string,
  audioStream: number, // index among audio streams, as in `-map 0:a:<n>`
  windows: readonly { start: number; duration: number }[]
) => Effect.Effect<SpeechWindow[], FfmpegError | SpeechActivityError>
```

The service chooses the audio stream from ffprobe's audio streams and their `language` tags: the one stream whose tag normalises to the media's original language, never `preferredLanguage`, the first stream, or a subtitle's language. `sampleSpeech` decodes each window of that stream as 16 kHz mono float32 PCM into a scoped temporary file, never through the text-collecting command helper, and runs Silero VAD (`src/integrations/ffmpeg/silero.ts`) with fresh recurrent state and context per window. The pinned Silero v5.1 model, its license, and its hashes live in `src/integrations/ffmpeg/silero/`; `onnxruntime-web` 1.22.0 runs on its WASM backend with one thread and no proxy worker, and the model and runtime assets are embedded in compiled binaries, so nothing downloads at runtime. Temporary files are removed on success, failure, and interruption, which propagates. Speech is sampled once per media per pass and shared by its English candidates; there is no persistent cache and no transcription. Logs carry per-window numbers and the selected stream, never cue text.

Persist `invalid` before sending the existing best-effort plain-text message to `TELEGRAM_CHAT_ID`: `Invalid subtitle for <media title> (<language>)`, with a `🗑️ Delete` button for that file (`[KD-15.1]`). After an automatic blacklist the message is instead `Blacklisted invalid subtitle for <media title> (<language>); Bazarr is searching for another.`, without a button (`[KD-18]`). Only the affected file alerts, at most once per file identity and version; `passed`, `inconclusive`, and repairs send no notification, and no message carries a file path. Telegram failure does not change the persisted verdict or stop other candidates; failed alerts are not retried.

### Invalid-subtitle actions

`/invalidsubtitles` replies `No invalid subtitles.` or `Invalid subtitles (tap to delete through Bazarr):` with one `🗑️ <file name>` button per current-version `invalid` path, ordered by path. Each button, like the invalid alert's, sends `subtitle_delete:<key>`, where the key is a base-36 `Bun.hash` of the full path because Telegram limits callback data to 64 bytes. The action answers the callback, then replies with the first matching outcome:

| Situation                                                  | Effect                                                                          | Reply                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------- |
| No current-version invalid path matches the key            | none                                                                            | `This subtitle is no longer marked invalid.`             |
| The file no longer exists                                  | remove the row                                                                  | `<file name> was already deleted.`                       |
| The file's size or mtime differs from the row              | none                                                                            | `This subtitle is no longer marked invalid.`             |
| Bazarr has no item or subtitle at that path                | keep the file and row; log a warning                                            | `Bazarr does not track <file name>; it was not deleted.` |
| Bazarr history holds a provider and `subs_id` for the path | Bazarr blacklists the subtitle, deleting it and searching again; remove the row | `Deleted <file name>.`                                   |
| Otherwise                                                  | Bazarr deletes the subtitle; remove the row                                     | `Deleted <file name>.`                                   |

The Bazarr item is resolved from the sibling media file `<base>.<video extension>`, trying the episode lookup before the movie lookup. A Bazarr failure (history lookup, blacklist, or delete) leaves the row in place and surfaces through the Telegram provider's generic error reply.

### Missing policy

```text
wanted ← bazarr.getWantedMovies() ++ bazarr.getWantedEpisodes()
rows ← repository.listMissing()
for each (item, lang) in wanted with lang not forced: upsert first_seen_at = now on absence
delete rows whose (item, lang) is not in wanted
for each row with first_seen_at < now - 3d and acted_at is null:
  item ← wanted[row]
  if item.subtitles (non-forced) is empty:
    telegram.sendMessage(TELEGRAM_CHAT_ID, "No subtitles for <title> after 3 days (missing: en, fr)")   # once per item, not per language
  else:
    source ← row.language = en ? first non-forced item subtitle
                               : non-forced en subtitle with a counting passed/audio row, smallest path   # [KD-19]
    if source is none → leave unacted; continue          # no request, no alert, no translation slot
    if fewer than 3 translation requests have been made this pass:
      bazarr.translateSubtitle(item, source, target = row.language)
      set acted_at = now on success
  else set acted_at = now after a successful alert
```

The all-missing alert groups every unacted row of one item into one message and marks all of them acted. At most three translation requests (including failed requests) are sent per pass across movies and episodes; excess rows stay unacted until a later pass. Alerts and rows waiting for a verified English source do not consume translation slots. A Bazarr or Telegram failure leaves `actedAt` null so the action is retried on the next pass. The policy never samples speech and never writes `subtitle_scans`.

### French profile policy

```text
if details.mediaType ≠ movie or details.preferredLanguage ≠ 'fr' → return
item ← bazarr.getMovieByPath(details.file)

Only exact matching Bazarr subtitle paths are removed; missing matches and failed deletes are logged and remain eligible on later passes. A French-audio movie never enters forced, speech, profile, repair, or blacklist analysis, whatever its scan row. Because the French preset requests only `fr:forced`, the missing policy's non-forced filter (`[KD-7]`) never alerts or translates for these items after assignment.
